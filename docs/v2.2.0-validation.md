# MacEase v2.2.0 validation

## Candidate

Version 2.2.0, build 8, Apple Silicon, macOS 26 or later. MacEase source remains
MIT. Download-only FFmpeg and LAME retain their LGPL licenses. Existing local
media engines and the self-signed release identity remain unchanged.

## Automated and independent checks

- `make build` succeeds with strict Swift/C warnings-as-errors. Xcode reports its
  existing optional App Intents extraction notice and unavailable iOS Simulator;
  neither is used by this macOS target.
- `make lint` passes.
- `make test-device` passes 1,235 tests: 57 MenuCatalog, 253 Formats and 925 Engine.
  An earlier parallel run missed the partial-output observation in the existing
  ZIP-preview cancellation test. The unchanged test passed alone and the later
  complete device run passed. No test condition was weakened.
- The compiled feedback fixture exercises the actual SettingsStore and
  UpdateChecker against isolated defaults: one-time migration, preserved later
  opt-out, reset-on behavior, and localized trusted official download URLs.
- Actual bundled tools and the real Engine pass fixed local MP4, separate-stream
  DASH, HLS, MKV/WebM/MP3 conversion, subtitle sidecars, collision-safe commit,
  cancellation, interrupted transfer and Undo checks.
- A read-only destination produces permissionDenied without final output or
  history. A disposable 32 MB HFS+ volume filled below the source size rejects
  the download without output or history. The test restores permissions and
  detaches/removes its disk image.
- A mixed successful/failed batch retries only the failed source after the
  controlled server recovers; the successful file remains byte-identical and
  no duplicate success appears.
- Explicit MP4 conversion of compatible H.264/AAC retains every video and audio
  packet SHA-256. A container with zeroed media payload is rejected by the full
  FFmpeg decode verification despite passing packet-count inspection.
- A generic two-video HTML playlist downloads only its selected second entry,
  verified against independent packet hashes. Re-analysis follows the current
  playlist index and checks the original media identity before transfer.
- The actual bundled yt-dlp filter parser accepts a literal ampersand in an ID,
  rejects another ID, and still rejects live media.
- Independent review findings on grouped subtitles, complete output validation,
  compatible stream copy, remaining weighted progress, HTTPS support and
  playlist filtering were corrected and reviewed again.

## Runtime and licensing

Private Python, Node, yt-dlp, EJS, FFmpeg and ffprobe run in a clean environment
from a relocated directory containing spaces. All 66 Mach-O components are arm64
and use system or relative bundled libraries, with no Homebrew/build-directory
runtime linkage. Python uses the system CA bundle. Node's restricted permission
mode is exercised. Python bytecode writes are disabled at execution.

Bundled FFmpeg disables GPL, nonfree and version-3 features. Its native Secure
Transport backend exposes HTTPS/TLS. A public 118-second AES-128 HTTPS HLS fixture
passes yt-dlp's FFmpeg fallback without Cryptodome, retaining normal certificate
verification; the final H.264/AAC output passes strict full decoding. The source
archive includes the exact pinned sources, EJS wheel, notices, build script,
manifest and LAME export patch.

## Physical Mac observations

The physical host runs macOS 27.2 with Xcode 27.2. In the Japanese/light app:

- Finder background yt-dlp opens a separate input window with that folder as
  destination. The actual app downloads YouTube `jNQXAC9IVRw`, TikTok
  `@scout2015/video/6718335390845095173` and Wikimedia `File:Example.ogg` together.
  Finder shows the WebM, MP4 and Ogg outputs in the requested folder.
- A selected folder becomes the destination. Separate invocations keep their
  own draft and destination; Escape dismisses the second without losing the first.
- Activity shows received-byte progress independently from `0 / 1 completed`.
  Closing Activity during transfer leaves the download running; Finder later
  shows a collision-numbered output in the selected folder.
- The developer extension initially omitted selected-item menus while duplicate
  build/install registrations existed. Removing the build registration and
  relaunching restored the menu. Temporary diagnostics then showed one folder,
  a valid directory hint and the expected menu callback. No classification
  workaround or entitlement expansion was added; diagnostics were removed.

## Website

The minimal English/Japanese copy changes pass Astro checks and build. The
existing complete browser verification passes. An earlier run missed its
unchanged offscreen-animation timing check under concurrent load; the same
browser suite passes on rerun without changing site animation or test criteria.

and keyboard flows, nonactivating delayed Activity behavior, final installed
settings/history continuity, and final signatures. After publication, verify
