# 45. Version 2.1 compression and UI stabilization

Date: 2026-11-02
Status: Accepted

## Context

The owner reported malformed editor toolbar controls and PNG target-size
compression taking over a minute before an unclear optimization warning.
The owner approved a debugging-focused release, complete UI audit and two
selected additions after reviewing domestic and international user feedback.

## Decision

Use balanced DEFLATE effort before maximum effort for size-target candidates.
Only try maximum effort when the same pixels do not fit, before reducing the
palette or resolution. Conversion uses balanced lossless effort. This removes
unnecessary compression search without changing image quality. Targeted
encodes cap their compressed output buffers and stop after a fitting filter.
An entirely unsuccessful bounded static-PNG search reports target failure
without a minimum-size estimate. Matched measurements found that repeating
every candidate solely for that estimate more than doubled some failure
latencies. Keep the original and offer editable retry; never invent a minimum.
Other formats retain their actual measured minimum-size reports.

Directly readable 8-bit RGB frames share exact pixels between lossless and
palette attempts. Reuse those pixels for factual reduction reporting, rather
than allocating another full raster. Other formats and precision paths retain
their existing decoding behavior. PNG filter zero writes each source row
directly, preserving the filtered byte stream and row-level cancellation.

Use scoped anonymous mappings for PNG filtering and libdeflate output
workspaces. Foundation owns each mapping with its original allocation length
and unmaps it on release. ADR 0046 extends this to mapped palette workspaces,
row-wise RGB access and final serialization, replacing the initial compressed-result copy with a
prefix view that retains its complete mapping owner. This avoids retaining
large freed heap workspaces under the OS deferred-reclamation policy.
Do not change process-wide allocator settings,
compression priorities, precision or the existing memory budget.

Palette candidates share one immutable decoded pixel buffer and may run in
parallel only within the existing frame-memory budget. Include retained images,
pixels, per-worker raster/output buffers and codec overhead in that budget;
reduce worker count when needed. Select the highest-priority fitting palette
regardless of completion order. Scope synchronous autorelease pools around
large temporary rendering and encoding work so successive scales do not retain
previous temporary buffers. Keep output pixels and the resolution search intact.

Continue splitting other palette regions when one region cannot split further.
A failed split must not truncate the entire palette and discard available color
precision. Independent decoded color/alpha checks cover the reproduced defect.

Implement SPEC section 21. Prioritize verified PNG latency, bounded workspace,
actual target attainment and clear outcomes. Preserve format and dimensions
before permitted lossy reduction. Separate image compression settings from
video while retaining existing saved behavior.

Add static-image result comparison and failure-only retry to the existing
Activity session. Keep request/settings snapshots in bounded session state;
do not introduce a persistent task database or change the Finder protocol.
Comparison reads verified originals, including recorded Trash locations.
Retry never repeats successful or explicitly cancelled work.

Version 2.1.0 uses build 7, three fresh GPT-6.1 Sol/high review rounds and the
existing local signing/publication process. The owner explicitly authorized
implementation, debugging, push and GitHub Release publication. Earlier
release-specific accessibility exclusions did not carry forward. The later,
explicit v2.1 VoiceOver scope decision is recorded in ADR 0047.

## Consequences

Quality, data safety and the existing memory budget constrain optimization.
Performance must be measured on completed output from matched Release builds.
UI acceptance includes actual rendering and operation; unavailable checks
remain unverified and cannot silently become release exclusions.
