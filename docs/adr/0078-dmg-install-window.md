# ADR 0078: DMG install window without Finder scripting

Date: 2026-11-24
Status: Accepted

## Context

The release disk image opened as a plain Finder window with MacEase and an
Applications link, with no indication of what to do. The common way to lay out
a disk-image window drives Finder with AppleScript while the image is mounted.
That needs Finder Automation consent, which CI runners and unattended local
builds cannot grant, and it makes packaging depend on a GUI session.

## Decision

Write the window layout deterministically. `make dmg` builds a writable HFS+
image, attaches it with `-nobrowse`, runs `make-dmg-window.swift layout` to write
the volume's `.DS_Store` directly, with a version-2 alias record for the
background picture and a buddy-allocated store, then detaches and converts the
image to ULMO before signing. The window is a 600 × 360-point icon view with the
toolbar, sidebar, status bar, path bar and tab bar hidden, 128-point icons,
13-point labels, MacEase at (160, 164) and Applications at (440, 164). The
background, regenerated by `make-dmg-window.swift background`, is a pale ground
with the app icon's highlighted menu row between the icons and no text, because
Finder draws labels black over a background picture in both appearances.

## Consequences

Packaging needs no Automation consent and produces the same layout every run.
The `.DS_Store` format is undocumented, so a future Finder could ignore or
reinterpret it; the image still opens with both icons in that case. The exact
window height, label placement and Dark Mode label colour have not been checked
in a real Finder window.

Alternatives rejected: AppleScript layout through Finder, for the consent
reason above; a dark background, on which Finder's black labels would be
unreadable.
