# MacEase v3.0.0 validation

## Candidate and scope

Version 3.0.0, build 9, arm64, macOS 26 or later. The physical host is an
M5 Mac with macOS 27.2 and Xcode 27.2. The existing MacEase Release identity
remains self-signed; Apple notarization is not claimed. GitHub Actions remain
disabled. Actual VoiceOver operation remains excluded under ADR 0048.

## Audio integrity

The resumed AAC changes passed current codec-delay, packet-copy and extraction
regressions, including the 100 ms gap after priming, AAC-LC native PCM equality,
and HE-AAC output-rate extraction in WAV, FLAC, MP3 and AAC. FFmpeg decoding of
AAC MP4 to MKV copies matches the source frames; the 136-frame HE-AAC shortfall
is fixed. ADR 0056 records remaining native Matroska SBR and MP4 priming limits.

## Toolkit and physical UI

The isolated QA application builds the real App sources and routes requests
through AppDelegate, PanelCoordinator and JobCenter using disposable fixtures.
Production settings and the user's clipboard are not changed by this harness.

- Japanese/light encryption and decryption retain the source and use collision
  naming. Decrypted bytes equal the source. A wrong password shows a localized
  failure and publishes no plaintext.
- Closing the failed Activity window and selecting Show Progress again does
  not restore the dismissed result. The regression tests separately preserve
  durable history and Undo. Actual Notification Center dismissal is not claimed
  from the window test.
- GUI image upscaling creates a 256 by 144 PNG from a 128 by 72 fixture.
  Speech cleanup produces a 16 kHz mono WAV; separation produces both 44.1 kHz
  stereo WAVs. All retain the two-second source duration and original files.
  Synthetic fixtures establish format and timing, not perceptual quality.
- The video editor displays the waveform lane and familiar timeline controls.
  Entering 0.250 to 1.750 seconds exports both streams at exactly 1.5 seconds.
- English/dark Download Media displays Video, Audio Only and Images. Images
  removes video-only controls. Inspect Source displays the independently checked
  SHA-256 and clearly distinguishes recorded links from authenticity evidence.
- Earlier in this implementation, actual gallery UI downloaded a public
  Wikipedia image with its source record. QR Start/Stop, wrong-token rejection
  and a byte-identical HTTP receiver were checked. Related-file search found
  the independent copy and Reveal selected it in Finder. Physical Android
  scanning was not tested.

Model source, licenses, weight comparisons and measured constraints are in
`ai-audio.md` and `upscaler.md`. Image input is limited to 1 MP opaque 8-bit SDR;
speech and stems are limited to ten and five minutes. Models ship with the app.
QR sharing is explicit, temporary, token-protected private-LAN HTTP, not TLS.

## Review and dependency checks

Fresh independent reviews covered toolkit integration and the later Activity,
update and HatchZip changes. Findings led to a verified-source rebuild for
HatchZip and update-label priority over other idle attention states. HatchZip
0.1.10 retains the existing archive scope. Completion metadata warnings reach
the standard job warnings. Exact upstream evidence and helper tests are in
`dependency-update-v3.md` and `hatchzip-update.md`.

The first resumed package run exposed an image menu ordering regression, fixed
without changing its test. An unchanged ZIP preview cancellation test missed
its short partial-output observation under parallel load and passed alone;
the final full-run result is recorded separately below.

## Storage cleanup

Removed 378 identified generated benchmark PNG/TIFF outputs from the two
v2.1.0 result directories: 16,521,747,954 logical bytes. Fixtures, measurements,
source, release artifacts and signing material were retained. APFS cloning
means this is not a claim of the same amount of newly free disk space.

## macOS 26 compatibility

The existing disposable VM runs macOS 26.6.2 (25G83), arm64, with 4 GiB RAM.
Actual age roundtrips, empty plaintext and wrong-password refusal pass there.
The same native GTCRN and Spleeter programs execute both models. Core ML loads
Swin2SR and predicts a nonconstant 128 by 128 output from 64 by 64 input.
HatchZip extracts its generated archive with exact output bytes. All 62 copied
resource hashes match before and after execution. Raw Spleeter CLI output is
136 frames shorter because of its STFT grid; the engine padding and assembly
are separately verified on the host to retain exact duration. This is distinct
from the corrected AAC packet-copy bug.

The actual QA application also launches on macOS 26. With an explicitly
seeded available-version value in isolated test preferences, the attention
icon appears and the update/download action is the first menu item. This
checks rendering and menu integration, not a fictitious public release.
The QA instance was quit after the check.

## Final release gates

Strict lint passes. `make test` passes all 1,313 package tests: 59 MenuCatalog,
261 Formats and 993 Engine tests, with zero skips. `make test-app` passes all
28 app-hosted tests. The sequential full package run also passes the unchanged
ZIP preview cancellation regression; ADR 0060 records the scheduling correction.

Full-device enforcement, final tagged DMG checks, installation, public asset
hashes and latest-release resolution are pending. Implementation checks above
do not substitute for these release gates.
